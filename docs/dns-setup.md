# DNS setup — ARTHVEX Mail

Nothing here may be copied into a customer zone until it matches **the actual mail engine
configuration and public IP of this deployment**. The application derives DKIM and MX values from
Stalwart (`domains.expected_records`) and never invents them. The authoritative per-domain list is on
the domain page (`/dashboard/domains/:id`).

## Pre-flight for the deployment host

| Check | Why | How |
| --- | --- | --- |
| Static public IPv4 (+ IPv6 if offered) | MX destination | `ip -brief addr`; provider console |
| Port 25 inbound **and** outbound | Inbound mail and direct delivery | `nc -vz <host> 25`, external test |
| Reverse DNS (PTR) for the mail IP | Receiving providers reject mismatches | Provider control panel; `dig -x <ip>` |
| `MAIL_HOSTNAME` A/AAAA | Client autodiscovery and MX target | `dig +short mail.example.com` |
| TLS certificate covers `MAIL_HOSTNAME` | SMTP/IMAPS/JMAP | `openssl s_client -connect mail.example.com:993` |
| Disk capacity + backup target | Mail storage growth | `df -h`, backup policy |
| Provider AUP allows port 25 | Some clouds block or forbid it | Provider documentation |

No change to production MX is allowed until inbound delivery is tested and a rollback (old MX with
TTL lowered at least 24 h earlier) is documented.

## Records per customer domain

Replace `mail.example.com` with `MAIL_HOSTNAME`, and take DKIM selector/key from the generated zone.

| Type | Name | Value | Notes |
| --- | --- | --- | --- |
| MX | `@` | `10 mail.example.com.` | Single correct MX set; engine-generated |
| TXT | `@` | `v=spf1 mx -all` | **Inspect existing senders first** |
| TXT | `<selector>._domainkey` | `v=DKIM1; k=ed25519; h=sha256; p=…` | Generated by Stalwart; never hand-edited |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s` | Start at `p=none` |
| TXT (ownership) | `_arthvex-verify` | app-generated token | Proves control before mailboxes |
| SRV | `_imaps._tcp` | `0 1 993 mail.example.com.` | Optional client discovery |
| SRV | `_submissions._tcp` | `0 1 465 mail.example.com.` | Optional client discovery |
| CNAME (optional) | `autoconfig` | deployment-provided autoconfig host | Only if the host serves it |
| TXT (optional) | `_mta-sts` | `v=STSv1; id=…` | Only with a working MTA-STS policy host |
| TXT (optional) | `_smtp._tls` | `v=TLSRPTv1; rua=mailto:tlsrpt@example.com` | TLS reporting |

## SPF rules

- Exactly **one** SPF record per name. Multiple SPF records break evaluation.
- Preserve legitimate existing senders (Google/Microsoft/marketing) by merging mechanisms inside the
  one record; do not delete them.
- The engine's outbound path must be covered by `mx` (single host) or `ip4:<public-ip>`.
- Use `-all`, not `~all`, only after every legitimate sender is included and observed in DMARC reports.

## DMARC rollout

1. `p=none` with reporting for at least two weeks while inventorying senders.
2. Confirm SPF and DKIM pass for all legitimate sources.
3. Move to `p=quarantine`, then `p=reject`, keeping `rua` reporting.
4. Keep alignment (`adkim`/`aspf`) at relaxed unless strict alignment is verified.

## Application verification behavior

- Ownership: server-side DNS TXT lookup (`DNS_RESOLVERS` optional), token hash stored, encrypted copy
  for display, expiry and rotation, background re-checks every 10 minutes for pending domains.
- Diagnostics: MX, SPF, DKIM, DMARC and mail-host checks are stored in `domain_dns_checks` with the
  observed value, status, message and timestamp. A frontend success response is never trusted.
- Mailboxes cannot be created on an unverified domain. If `mailbox_creation_requires =
  ownership_and_mx`, inbound MX must also pass.
- Propagation: DNS changes can take the record TTL to appear; the UI reports the last check time and
  offers a manual re-check rather than pretending success.

## Never do

- Do not auto-edit customer DNS unless an explicitly configured provider integration is authorized.
- Do not reuse DKIM private keys across domains; they stay inside Stalwart and are never displayed.
- Do not point MX at a host that does not accept port 25.
- Do not place the Stalwart management port or setup wizard behind public DNS.
